**The two headline numbers are the same defect measured twice.** `tw-max-w-lg` centres a 512px
column on a 1440px viewport, so 64% of the screen is empty and the admin sees **2.5 matchups at a
time**. Running a 32-player round means scrolling roughly 13 screens to read 16 rows.

**Tells visible in the baseline** (from `SKILL.md`):

1. **Tell 7 — everything is a card, nested twice.** Outer card per matchup, inner card per player,
   ~200px of vertical space to carry two names and a score.
2. **Tell 6 — uniform whitespace regardless of task.** This is an admin work surface being laid out
   like a marketing page.
3. **Tell 5 — spinner-first loading**, where the arriving layout is entirely known.
4. **Tell 4 — one empty state doing several jobs.** Worse: `empty-first-run` renders *nothing* —
   header and search box over blank space, no message and no action.
5. **`Great League` repeated 16 times**, once per row, in each row's most prominent slot. The meta
   is constant for the whole tournament; it is noise holding the title position.

**A defect the state harness found that a screenshot would not:** `error-recoverable` (500),
`permission-denied` (403) and `not-found` (404) all render the **identical** screen — *"You must
have admin permission to view and manage tournament settings"* with a Navigate-back button. A server
error and a missing tournament both tell the user they lack permission. Wrong, and unactionable.

## 4 · State inventory and manifest (step 4)

8 states × 2 surfaces = 16, all `forceable`, generated by `build-manifest.mjs` into `states.json`.
**0 unforceable, 0 force-failed.**

`dense · single-item · empty-first-run · overflow · loading-initial · error-recoverable ·
permission-denied · not-found`

**Forcing this app takes a four-part auth preamble**, at manifest level:

1. `zygardenSession` cookie — `hasSession()` gates the refresh entirely.
2. `**/.well-known/openid-configuration` stub — the refresh needs a discovery document first.
3. `**/auth/refresh` stub returning **camelCase** `{ accessToken, expiresIn }` with a JWT-shaped
   token. The BFF transforms OIDC's snake_case, and the app parses the token for the user's name.
4. `consentAnalytics` in localStorage, set to **declined** — otherwise the cookie banner covers
   every cell of the contact sheet.

The access token is an **in-memory Angular signal** and the refresh token is an **HttpOnly cookie**.
Nothing is in localStorage to seed, so `force: auth` as originally specified could not have worked
here. This is the modern BFF pattern, not an oddity.

## 5 · Comps (step 5) — awaiting the kill

Two directions for `manage-matchups`, both **state-complete at both surfaces**: 8 states × 2
surfaces × 2 directions = 32 shots, **0 holes, 0 unforceable, 0 force-failed**.

Built as standalone pages consuming the app's **real** `tokens.css`, not as edits inside
`zygarden-frontend`. The repo sits on `feature/component-api-convergence` and comps are throwaway
by design; building two of them into the user's feature branch is not a decision to take
unattended. **Recorded as a deviation from "in real code"**, with that reason.

**Direction A — the register.** One row per matchup, full width, the row as the unit of action.
Bracket order preserved. Scores editable in place, sequentially.

**Direction B — the round board.** Grouped by what the organiser must *do*: "Needs you to decide",
"Waiting on players", then "Settled" as a dense list. Cards only where each item is a decision.

| Measure | Baseline | A | B | Canon |
|---|---|---|---|---|
| Type contrast | 2.14 | **2.55** | **2.55** | 2.0–2.67 ✓ both |
| Type weights | 400/600/700 | 400/600 | 400/600 | 400/600 ✓ both |
| Body size | 16px | 12px | 13px | 14px — **both below** |
| Spacing steps | 5 | 4 | 4 | 5–10 — **both below floor** |
| Colours (3+) | 8 | 5 | **9** | 7–14 — A below, B in band |
| Component reuse | 0.662 | **0.912** | 0.59 | median 0.78 — A near Airbnb, B below |
| Targets / megapixel | 3.9 | **23.1** | 10.8 | 12.7–151 — A in band, **B below floor** |
| Matchups in viewport | 2.5 | **12** | 7 | — |
| axe + focus + keyboard | — | **0 / 0 / 0** | **0 / 0 / 0** | both clean |

**A measures better; B thinks better.** A wins on density, reuse and interactive target count. B's
grouping is the stronger product idea — an organiser closing a round cares about the two matchups
outstanding, not the fourteen settled — but its execution fails two canon floors: reuse 0.59 (cards
are bespoke) and 10.8 targets per megapixel (two mostly-empty group boxes dominate the top half
whenever the outstanding count is low, which is the common case late in a round).

**Defects both directions still carry**, to fix in whichever survives:

- **Body at 12–13px against a canon 14px.** Both overcorrected from the baseline's 16px.
- **4 spacing steps against a canon floor of 5.**
- **Mobile chrome eats ~40% of an 844px viewport** before the first matchup: title, three chips,
  subtitle, a five-button round switcher wrapping to two rows, then search. The round switcher is
  the main cost and should collapse to a select on small screens.

### Findings against zygarden's own design system

Two status token pairs fail WCAG AA **as the system pairs them**, on the default dark theme:

| Pair | Measured | Needs |
|---|---|---|
| `--color-status-info-text` on `--color-status-info-bg` | **4.44:1** | 4.5:1 |
| `--color-status-danger-text` on `--color-status-danger-bg` | fails at 11–13px | 4.5:1 |

These were found by pairing the tokens exactly as intended, not by misusing them. The crosswalk
reports `validatorPassing: true` with zero drift across all 225 variables — **drift verification
checks that Figma and code agree, not that the result is legible.** Both comps work around it by
keeping the status background as the signal and taking `--color-text-primary` for the text; the
real fix belongs in the token set, which this run is **read-only** against.
